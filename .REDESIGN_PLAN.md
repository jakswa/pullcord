# Rail Redesign Plan

## Recommendation

Keep Tailwind for the rest of Pullcord, but make rail a custom, self-contained CSS island. Rail already ships inline CSS from `src/views/pages/rail/styles.ts`, so the cleanest path is to replace that rail CSS wholesale with prototype-derived custom CSS and avoid pulling the global Tailwind bundle into rail pages.

Start with system fonts. The redesign uses Archivo and Spline Sans Mono, but custom fonts add mobile weight and require self-hosting because the current CSP allows `font-src 'self'`. Leave CSS variables ready for future font slots.

If custom fonts are added later, subset them with `pyftsubset` from `fonttools` or `glyphhanger`.

## Files To Touch

- `src/views/pages/rail/index.tsx`
- `src/views/pages/rail/data.ts`
- `src/views/pages/rail/styles.ts`
- `src/views/pages/rail/client.ts`
- `src/data/rail-colors.ts`, only if line colors should match the redesign exactly

Do not edit `public/styles.css`.

## Target Mapping

- `/rail`: redesigned home screen
- `/rail/:slug`: redesigned station board
- `/rail/train/:trainId`: redesigned train timeline

## Implementation Steps

1. Replace the rail view model in `src/views/pages/rail/data.ts`.

Keep existing canonical station/order helpers. Add helpers for station lines, sorted arrivals by station, soonest arrival per direction, later arrivals per direction, and ETA state.

2. Rebuild `/rail` as the redesign home.

Header shows `marta.io` and live freshness. Favorite stations become large hero cards. One favorite renders as one big card. Multiple favorites stack vertically as full-width hero cards. If there are no favorites, show a small empty-state card telling the rider to star a station.

Nearby remains secondary and opt-in using the current geolocation flow. All stations becomes a searchable row list.

3. Port prototype atoms into Hono JSX.

Create small components like `LineChip`, `LineDots`, `DirectionToken`, `HeroStationCard`, `StationListRow`, and `RowTime`. Use existing `RailArrival` data directly. Do not add React or a client framework.

4. Rebuild `/rail/:slug` as the station board.

Header includes back button, station name, line chips, favorite star, and freshness. Add direction filter buttons for `all`, then available directions. Render all rows server-side with `data-dir`; client JS hides/shows rows without another request.

5. Rebuild `/rail/train/:trainId` as the train timeline.

Keep the current timeline data algorithm. Restyle it like the redesign. Dim passed stops instead of hiding initially visited stops. Mark the next/current stop with line color and pulse.

6. Rewrite `src/views/pages/rail/styles.ts`.

Use rail-specific class names only. Define tokens for background, surfaces, text, hairlines, accent, line colors, UI font, and data font. Preserve mobile-first legibility from `reimagine/marta/HANDOFF.md`.

Use system stacks initially:

- UI: `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
- Data: `ui-monospace, "SFMono-Regular", "Cascadia Code", Menlo, Consolas, monospace`

7. Rewrite `src/views/pages/rail/client.ts`.

Keep polling and freshness behavior. Preserve `rail-starred` compatibility. Add landing enhancements for favorite hero stack, nearby, all stations, search, and stars. Add station enhancements for favorite button and direction filter. Remove the old train script that hides initially visited stops.

8. Keep routes unchanged.

`src/routes/rail.tsx` should continue serving full pages and partials through the same component entry points.

## Font Follow-Up

Ship system fonts first. If custom fonts are worth the weight, self-host tiny subsets under `public/fonts/`.

Likely subset weights:

- Archivo: `700`, `800`, maybe `900`
- Spline Sans Mono: `600`, `700`

Use `font-display: swap` and keep CSP as `font-src 'self'`.
